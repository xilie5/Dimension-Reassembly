# Compound Box - 可执行升级计划

## 1. 升级目标

把当前 6 关、3 个核心动词的可玩原型，升级为：

- 15 关完整垂直切片
- 5 个递进区域
- 支持逐格材质和复合目标
- 支持精确切割、旋转和可移动传送节点
- 具备可复用的关卡编辑、验证和求解工作流
- 保持 Windows Player 可构建、自动化测试全绿
- 可作为 Unity 程序、游戏玩法程序或技术设计岗位的作品集项目

目标版本：`1.0 Portfolio Slice`

预计工作量：

- 全职熟悉代码的开发者：5 到 7 周
- 业余每晚 2 到 3 小时：10 到 12 周
- 如果只完成 P0 内容：3 到 4 周

## 2. 范围冻结

### 本阶段必须完成

- 逐格材质复合体
- 复合目标形状与材质校验
- 移动、传送、拆分、重组、精确切割、旋转
- 可移动传送节点
- 15 关教学曲线
- 编辑器验证和标准解法回放
- 关卡主题、HUD、反馈和音效

### 本阶段明确不做

- 递归空间或盒子套盒子
- Snakebird 式重力系统
- 战斗、敌人和生命值
- 实时计时和限时关卡
- 随机生成关卡
- 在线系统
- 复杂剧情分支
- 完整化学价键模拟

## 3. 设计约束

每个新机制进入正式内容前必须满足：

1. 能在一屏房间内表达。
2. 一个动作能在 3 秒内看清结果。
3. 失败后可立即撤销或重开。
4. 能与至少两个已有机制组合。
5. 可以通过数据验证和标准解法回放。
6. 不需要依赖大段教程文本。

每个正式关卡必须满足：

- 棋盘不超过 `14 x 10`
- 可移动实体不超过 4 个
- 只引入一个主要新概念
- 标准解在 8 到 25 个动作之间
- 不含不可恢复的隐藏死局
- 至少有一种已知解法

## 4. 工作流划分

```text
数据模型 V2
    -> 规则与 Command
        -> 表现与预览
            -> 编辑器与验证
                -> 15 关内容生产
                    -> 表现打磨与作品集交付
```

场景美术和音效可以在机制稳定后与关卡制作并行，但不能早于规则冻结，否则会反复返工。

## 6. M0：设计和数据结构冻结

### 任务

#### M0-1 冻结 15 关机制顺序

输出：

- 每关 ID
- 新机制
- 可复用的旧机制
- 预计动作数
- 目标情绪和主要 aha

#### M0-2 冻结 Schema V2

确定以下数据的持久化格式：

- 每个格子的材质
- 实体内部连接边
- 复合目标的形状与材质
- 可移动传送节点
- 关卡版本号

#### M0-3 建立迁移规则

- 当前 6 关继续使用 V1 文本布局
- 新机制关卡使用 V2 数据
- V1 关卡加载后转换为 V2 运行时格式
- 存档增加 `schemaVersion`

### 验收标准

- 不修改代码也能明确描述所有 15 关
- 每个机制都有第一关、对照关和组合关位置
- V1 到 V2 的迁移边界明确

## 7. M1：Grid Entity V2

当前问题：

- `GridEntity` 只有一个 `MatterType`
- 一个复合体不能同时包含不同材质
- 实体只有格子集合，没有连接边
- 无法表示“从哪条连接切开”和“从哪两个端点重组”

### 新增或改造

#### M1-1 EntityCellState

每个格子保存：

- `Vector2Int Position`
- `MatterType Matter`

#### M1-2 EntityConnection

每条连接保存：

- 两个相邻格子
- 可选的连接规则

#### M1-3 GridEntity V2

```text
GridEntity
  Id
  Kind
  EntityCellState[]
  EntityConnection[]
```

#### M1-4 兼容属性

为了降低迁移风险，暂时保留：

- `PrimaryMatter`
- `Cells`
- `Anchor`

旧代码先通过这些兼容属性工作，再逐步移除。

#### M1-5 Clone、Restore 和 Hash

必须完整复制：

- 格子材质
- 连接边
- 实体 ID
- 锚点

### 涉及文件

- `GridEntity.cs`
- `GridBoardState.cs`
- `GridBoardSimulation.cs`
- `LevelParser.cs`
- `LevelDefinitionAsset.cs`
- `ArchitectureTests.cs`

### 验收标准

- 当前 6 关回归测试全部通过
- 一个复合体包含两种材质时，移动和传送保持所有格子材质
- 撤销和重做不破坏新材料数据

## 8. M2：变换预览和旧关卡回归

### M2-1 移动 Ghost

玩家按键前显示候选位置：

- 合法移动：青色轮廓
- 推动：目标物使用琥珀轮廓
- 非法移动：红色轮廓

### M2-2 传送 Ghost

复合体进入传送门时：

- 显示整个形状在出口的预览
- 显示起点到出口的连线
- 如果出口被占据，整个预览变红

### M2-3 变换预览接口

统一预览结构：

```text
TransformPreview
  EntityId
  SourceCells
  TargetCells
  Validity
  Reason
```

后续切割和旋转复用这一结构。

### M2-4 旧关卡回归

- 重新截取 1 到 6 关首屏
- 检查传送门、目标、出口和 HUD 不重叠
- 回归全部标准解法

### 验收标准

- 玩家能在执行动作前预知传送结果
- 非法传送不会出现闪烁后失败
- 1 到 6 关视觉和逻辑无回归

## 9. M3：多材质和复合目标

### M3-1 逐格视觉

`EntityCellView` 根据格子材质配置颜色，不再读取实体统一材质。

### M3-2 连接线

同一实体相邻格子之间绘制：

- 同材质连接：实线
- 异材质连接：双色线或接缝
- 非法或断裂连接：缺口

### M3-3 复合目标 V2

目标保存：

- 所需轮廓
- 每格材质
- 是否要求全部连接

### M3-4 材质过滤器

传送门或目标可以声明：

- 接受材质白名单
- 拒绝材质黑名单
- 是否需要多个材质同时到达

### M3-5 关卡内容

新增：

- 双材质复合体
- 同形状不同材质目标
- 材质过滤传送门
- 复合分子目标

### 验收标准

- 颜色只表达材质，形状只表达结构
- 目标与实体在视觉上可以一一比对
- 不同材质不能错误重组

## 10. M4：连接图和精确切割

### M4-1 连接连通性

复合体由图结构描述：

```text
Node = EntityCellState
Edge = EntityConnection
```

### M4-2 精确切割

新增 `PrecisionCutCommand`：

- 选择一条面向玩家的连接边
- 切断该边
- 将实体拆分为两个连通分量
- 保留每个分量内部连接

### M4-3 合法切割验证

切割后两个组件必须：

- 都至少包含一个格子
- 不与墙或第三实体重叠
- 不丢失材质
- 不产生零长度连接

### M4-4 重组端点

重组条件从“任意相邻”升级为：

- 端点材质匹配
- 端点方向匹配
- 符合关卡允许的连接规则

### M4-5 内容

- 二格连接切割
- L 形组件切割
- 切割后通过窄道
- 切割后从另一端重组

### 验收标准

- 切割和重组不会复制或丢失格子
- 连接边在 Undo/Redo 后完全恢复
- 至少三关依赖精确切割才能完成

## 11. M5：复合体旋转

### M5-1 RotateCommand

- 围绕实体锚点旋转 90 度
- 顺时针和逆时针由输入决定
- 保存旋转前的连接图

### M5-2 占用验证

旋转后检查：

- 所有格子在地图内
- 不碰到墙
- 不与其他实体重叠
- 不触发非法传送

### M5-3 预览

旋转前显示目标轮廓：

- 合法：青色或材质色
- 非法：红色

### M5-4 教学内容

- 窄道旋转
- 两格横向变纵向
- L 形转向
- 旋转后材质仍满足目标

### 验收标准

- 旋转保持所有连接关系和材质
- 连续四次旋转回到原始状态
- Undo 后完全恢复

## 12. M6：可移动传送节点

### M6-1 PortalNodeEntity

传送节点拥有：

- 占有格子
- 配对节点 ID
- 固定端或移动端类型

### M6-2 动态 Portal 映射

传送目标不再来自静态字典，而是每帧或每次状态变更后重建：

```text
PortalId
EntryNodePosition
ExitNodePosition
```

### M6-3 推动节点

节点可以参与推挤链，但不能：

- 与另一节点重合
- 被拆成单格
- 被目标判定为普通材质

### M6-4 内容

- 推动出口改变路线
- 封堵一个出口后启用另一条路线
- 节点与复合体同时推挤
- 两套传送网络交叉

### 验收标准

- 节点移动后所有传送立即使用新位置
- 节点移动可以撤销
- 节点状态被完整存档和恢复

## 16. 测试计划

### 核心不变量

- 每个格子最多被一个实体占用
- 实体所有格子都在地图范围内
- 连接边两端都存在且相邻
- 切割前后格子总数不变
- 重组前后格子总数不变
- 旋转前后材质与连接总数不变
- Undo/Redo 后状态哈希一致

### 内容测试

- 标准解法完成关卡
- 错误一步不会破坏存档
- 目标材质和形状同时满足
- 动态传送节点位置更新正确
- 旧存档可以升级

### 性能测试

- 目标：Windows 构建 60 FPS
- 单次动作不产生明显 GC
- 预览对象和实体格子复用对象池
- 15 关切换不持续增长内存

## 17. 风险控制

| 风险 | 控制方式 |
| --- | --- |
| 数据模型升级破坏旧关卡 | 保留 V1 解析和回归测试 |
| 新机制过多 | 每个里程碑最多引入一个主动词 |
| 关卡难做 | 先完成编辑器和求解器，再批量制作 |
| 传送规则难懂 | 加入 ghost 和位置预览 |
| 多材质不可读 | 颜色只表达材质，形状只表达结构 |
| 切割导致状态爆炸 | 限制一关最多四实体 |
| 预览影响性能 | 复用对象池，不在每帧分配 |
| 内容拖垮进度 | 优先完成 P0 的 12 关，再扩展 15 关 |

## 18. 最终验收

升级完成必须同时满足：

- 15 关全部可完成
- 15 关拥有标准解法和验证报告
- 6 个核心动词都可教学和组合
- 20 个以上自动化测试通过
- 完整通关流程可以存档和恢复
- Windows 构建成功且无错误
- 有一分钟演示、三张截图和完整设计文档
- 面试时可以用 10 分钟讲清规则、架构、工具和关卡方法

## 19. 推荐执行顺序

不要先做场景装饰，也不要一次性开发全部高级机制。

推荐严格按以下顺序：

```text
Grid Entity V2
  -> 变换预览
  -> 多材质
  -> 复合目标
  -> 精确切割
  -> 旋转
  -> 可移动传送节点
  -> 15 关内容
  -> 主题表现
  -> QA 和作品集包装
```

这样每个阶段都能得到可运行、可测试、可展示的增量版本。
